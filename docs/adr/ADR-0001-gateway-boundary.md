# ADR-0001：Gateway 独立边界与路径契约

- 状态：已接受
- 日期：2026-09-02
- 决策范围：Git 仓库、服务边界、外部路径与路由事实源

## 背景

Vireon 的 IAM、Audit、未来 System 和 QBC 服务需要稳定的统一外部入口，同时必须保持下游服务
能够独立构建、运行和执行权限校验。Gateway 的发布节奏、边缘安全和运行资源也不应与任一业务服务
或 Framework 绑定。

## 决策

1. Gateway 使用独立 `vireon-gateway` Git 仓库、Maven 根、版本、制品、进程、镜像和部署单元。
2. Gateway 不进入 Framework，也不依赖 Platform/QBC 内部 Java 类型、数据库、源码或构建输出。
3. 外部路径固定为四组精确前缀：`/api/iam`、`/api/audit`、`/api/system`、`/api/qbc`，同时匹配
   前缀自身及其 `/**` 子路径。
4. Gateway 将完整路径原样转发，禁止 `StripPrefix`；下游 API 自身使用相同的 `/api/<service>` 前缀。
5. 匹配以路径段为边界，`/api/iamx`、`/api/auditing` 等相邻字符串不属于目标路由。
6. 首期只在 IAM 和 Audit 服务真实可用后激活其路由；System 与 QBC 服务创建前对应路径保持 404。
7. 每个运行环境只能选择静态描述或显式 Nacos 路由作为权威源，两种模式必须保持路径契约等价。
8. Gateway 负责路由、边缘安全和流量治理；身份、授权和业务校验仍由数据所有者服务负责。

## 结果

- 客户端、OpenAPI `servers`、回调地址与 SDK 可以长期使用稳定前缀，不依赖内部发现方式。
- 下游服务直连也使用完整路径，避免 Gateway 与服务端维护两套 URL。
- 新服务不能仅通过添加占位路由宣称已接入；必须先有可运行下游和相应契约测试。
- 静态与 Nacos 模式需要共享同一类型化路由模型或等价验证，不能产生双重事实源。

## 当前不实施

- 本 ADR 不授权创建 Maven 工程、活跃路由、Nacos 配置、镜像或部署脚本。
- 本 ADR 不定义限流数值、认证协议、可信代理清单、域名、端口或生产基础设施参数。
- 未出现真实聚合用例前，不引入 DTO 聚合、响应改写或跨服务编排能力。
